# アーキテクチャ

## 保存と解析の流れ

```text
React UI → preloadの限定IPC → Electron main → SQLiteへ原文を保存
                                              ↓
                                   分類・Digestの待機ジョブ
                                              ↓
                                   Codex App Server → 結果検証
                                              ↓
                                  原文版が一致する場合だけ採用

Ask → ローカル候補検索 → 対象の原文 → Codex → 主張・根拠を保存
```

メモの保存はAI処理の完了を待ちません。分類先はユーザーが作った既存カテゴリに限り、不明なものはOtherに残ります。カテゴリ候補は提案として表示し、作成はユーザーが行います。

CollectionsのDigestは原文の要約・主張・反例・時期を保持します。Next Stepsはその解析結果の提案を表示します。Askでは質問に関係する原文を検索し、任意で現在のDigestの根拠を候補選びに加えます。Askへ送る証拠は原文であり、過去のAI文章を本人の事実として再利用しません。

## データの分離

- **原文**：notes、note_revisions、attachments、出典区分と元URL。
- **所属**：categories、assignments、手動除外、カテゴリ改変の履歴。
- **AI出力**：runs、outputs、claims、evidence、解析に使った全原文版。
- **評価**：feedback、訂正コメント、参照元runとの依存関係。
- **処理状態**：分類・Digestジョブ、検索用キャッシュ、下書きと設定。

Good／Badは回答への評価です。モデルの再学習は行わず、後のプロンプトで評価と訂正を参照します。AIが生成した下書きは原文の証拠から除きます。

編集・削除・カテゴリ変更後は古い入力版に依存する解析を無効にします。処理の停止・再試行ではトークンを変え、遅れて届いた結果による上書きを防ぎます。メモをAI解析対象外にすると、そのメモと関連する評価に依存する解析もAI入力から除きます。

## GraphとUI

Mac版のGraphは現在のメモとカテゴリ所属を表示します。AIが見つけた意味的な関連を表すものではありません。最新160件を対象とし、対象外設定のメモもローカル表示には残ります。

UIはReact、SVG、Canvas、CSSを使用します。入力はRaycastのようなクイック入力です。全画面が軌道表示と同じ言語で組まれています。共通部品（黒い面・ピル・ボタン・しずく・波紋・円・目盛り・スイッチ）は `app/src/UiPrimitives.jsx` と `app/src/pure-ui.css`、書体と色の変数（`--font-display` / `--font-text` / `--font-mono`）は `app/src/fonts.css` にあります。円を置く画面（提案・質問・ごみ箱）と軌道は、背景の穴の基準位置 `app/src/hole.js` を共有します。背景の上に直接置く文字は、背景が最も明るくなる瞬間でもコントラスト比4.5:1以上になる色にし、足りない箇所はピルを敷いています。画面の切り替えはView Transitions（`DesktopApp.jsx` の `transition`）で行い、ページ間は上方向へのフェード、軌道とリストの切り替えは横スライドです。背景と表示切替のスイッチは動かしません。動きを減らす設定では切り替えアニメーションを省きます。動きを減らす設定と非表示時のアニメーション停止を維持します。

メモ画面の既定は「軌道」表示です（`app/src/OrbitView.jsx`、幾何は `app/src/orbitLayout.js`）。中央の入力円の周りに新しい順で最大4件のメモを置き、それ以前は「+N 以前のメモ」として従来のリスト表示へ送ります。メモとカテゴリをつなぐ点線は、保存済みのカテゴリ所属と分類ジョブの状態だけから描きます。分類ジョブが待機中・実行中のメモは「分類待ち」、所属もジョブもないメモは「未分類」として表示し、分類結果を推測で描きません。表示の切り替えは「軌道 | リスト」で行い、リストは従来の一覧画面です。

## クイック入力

⌘⇧N は、前面のアプリからフォーカスを奪わない入力パネル（`type:'panel'`、`app/desktop/capture-window.cjs`）を開きます。開く前に `app/native/context-helper`（`context.swift`）が、前面アプリ・ウィンドウ名・ブラウザのタブのURLとタイトル・選択中のテキストを読みます。選択テキストはアクセシビリティAPIで読み、取れないアプリでは ⌘C を送ってクリップボードを元に戻します。パスワード入力中（Secure Input）、パスワード管理アプリ、設定で除外したアプリからは何も読みません。

選択テキストは引用（`note_revisions.excerpt`）として、入力した言葉は本人の考え（`body`）として保存します。引用だけなら従来どおり `quote` のメモです。AIには「excerptは外部の文章で本人の意見ではない」と伝えて渡します。同じURLから10分以内に取り込んだときは、前のメモへの追記を提案します。直前30秒のコピー（パスワード管理アプリの項目は除く）と、直前2分のスクリーンショットは、取り込み候補として出します。

⌥⌘⇧N はパネルを出さずに選択テキストを出典付きで保存し、取り消せる通知を出します。`pure://new?text=&quote=&url=&title=` はパネルを開いて内容を入れるだけで、リンクだけでは保存しません。必要な権限はアクセシビリティ（選択テキスト）とオートメーション（ブラウザのURL）です。配布用のInfo.plistには `NSAppleEventsUsageDescription` を入れてください。

## 表示言語とモデル

UIは日本語と英語を切り替えられます（設定 › 一般 › 言語）。文字列は日本語の原文をキーにした `t()`（`app/src/i18n.js`）で表示し、英訳は `app/src/i18n-en.js` にあります。`i18n.test.js` が、すべての `t()` に英訳があり、差し込み値の名前が一致することを確認します。メモの本文とAIの回答は翻訳しません。保存・復元のダイアログもこの設定に従います。

Codexのモデル一覧はApp Serverの `model/list` を全ページ読み、起動時・設定を開いたとき・ウィンドウに戻ったとき（10分ごとまで）・手動更新で取り直します。新しく出たモデルは通知し、選んでいたモデルが消えた場合は既定のモデルに戻します。推論の強さ（high など）はモデルが公開している値だけを選べます。値は `app_state` に保存し、自動分類やまとめを含むすべての `turn/start` に `effort` として渡します。処理するモデルがその値に対応していない場合は送らず、モデルの既定値を使います。

## 記憶の層

保存したメモは、自動処理がオンなら1回だけ読みます（`classifier.cjs`）。リンクのないメモは最大6件を1回の呼び出しでまとめ、カテゴリ分けと同時に「メモから本人について分かること」（何について・どう思っているか・好み/したこと/したい/習慣/考え・本人の言葉か外部か・時期）を、メモの原文の引用つきで取り出して `memory_facts` に保存します。引用が原文にないもの、対象がメモやリンク先にないものは捨て、取り込んだ引用文（excerpt）だけからの記録は外部の言葉として扱います。記憶の層ができる前のメモは、モデルが分かった時点で「記憶だけ読む」ジョブとして後から読み、既存のカテゴリには触れません（`queueMemoryBackfill`）。

各機能は生のメモを毎回読み直す代わりにこの層を使います。ニュースの関心探しは全メモの記録を「何について」ごとに集計して材料にし（`interestSubjects`、記録がまだなければメモの見本に戻る）、質問の検索は記録の文から元のメモへたどれる候補を加えます（`memory-assisted`）。メモをAI解析の対象外にするか削除すると、その記録も消えます。

## AIの接続先とモデルの使い分け

すべてのAI呼び出しは `ai-router.cjs` を通ります。接続先は設定で Codex（`codex.cjs`）と Claude Code（`claude-code.cjs`）から選べ、どちらもこのMacのCLIを利用者のアカウントで使います。Claude Code は `claude -p` を構造化出力で呼び、ツールなし（ニュースの収集だけWeb検索）、ユーザー・プロジェクト設定とMCPを読まず、会話を保存せず、空の作業フォルダと pure 専用の前提指示で動かします。

保存時の分類と読み取り、回答の検証、見出しの翻訳は「軽い処理」として、設定の「軽い処理のモデル」（既定は選んだモデルを推論 low で）で動かします。それ以外は選んだモデルと推論の強さを使います。ジョブに残ったモデルが今の接続先で使えないときは、その接続先の既定のモデルに置き換えます。

## まとめの安定

まとめを作り直すときは、前回のまとめの主張のうち、根拠の原文がすべて今の入力にあるものを渡し、変わっていない主張は言い回しを保つよう求めます（`previousDigest`）。Bad と評価されたまとめ、AI解析の対象外で止めた実行のまとめは渡しません。前回の文章は根拠に数えず、検証も通常どおり行います。

## プロフィール

記憶の層（正本）の上に、「この人の今」を表す小さなプロフィールを持ちます（`profile.cjs`、`memory_profile`）。記録を「何について」ごとに手元でまとめ（AIは使わない）、各トピックについて「本人との今の関係を1文」と「続いている／過去／不明」をAIが書きます。各行はどの記録から作ったかを持ちます。

- 更新: メモが読まれて少し落ち着いたら、記録が変わったトピックだけを書き直します（軽い処理）。
- ずれ対策: 週1回とプロンプトの版が変わったときは、前回の文を使わず記録だけから作り直します。
- 削除: メモをAI解析の対象外にするか削除すると、その記録を使った行をすぐ消し、次の更新で残りの記録から書き直します。
- 利用: 質問には参考情報として渡し（根拠には使わず、主張は原文で確かめる）、ニュースの関心探しでは「過去」のトピックを除きます。

既存メモの記憶だけの読み込みは、1回の呼び出しで最大20件をまとめて読みます。

## 根拠の検証

まとめと質問は、生成と形式の検証（落ちたら理由を添えて1回だけ答え直す）のあと、保存前に `verify.cjs` で、主張と要約の各文が引用したメモ（日付つき）だけで言えるかを別の呼び出し（推論は軽め）で確かめます。言えないものは取り除き、何も残らなければ「根拠のメモで確かめられる内容がありませんでした」として扱います。確認の呼び出し自体が失敗したときは結果をそのまま通し、`ai_calls` に記録します。

## リンクの読み取り

リンク付きのメモは、`article-worker.cjs` がリンク先を読み（YouTubeはページ内の動画情報と「音楽」欄の曲名・アーティスト・アルバム）、続く分類ジョブ（`classifier.cjs`）が同じCodex呼び出しで、種類・作品名・作者・メモの指示（後で聞く／見る／読む など）・表示言語での要約を返します。作品名と作者は資料かメモに含まれる文字列だけを残し（`readLink`）、結果は版ごとに `link_readings` へ保存します。AI解析の対象外にすると削除します。

## ニュース

「集める」（オンなら毎日1回、1時間ごとに確認）の1回で、次をすべて行います（`news.cjs`）。

1. メモから具体的な関心を探す（`interests.cjs`）。他のAI解析と同じくメモをCodexへ送り、アーティスト・作品・人物・技術などを、検索語・理由・根拠の引用つきで返させます。引用が原文にないものは捨てます。AIが読めるメモが前回から変わっていなければ（`interestFingerprint`）前回の結果を使います。
   続けて、見つかった関心から「それが好きなら気になりそう」な別の具体的なもの（監督の新作、メンバーのソロなど）を最大4つ広げます（`relatedPrompt`、関心ごとに2つまで）。メモに書かれていない AI の推測なので、元の関心（`from`）と関係の理由を持たせ、画面では「関連」として分けて表示し、記事も「〈元の関心〉が好きなら」の枠に分けます。外した言葉は次に広げるときに渡し、似たものを出させません。この依頼に送るのは関心の名前と理由だけで、メモや引用は送りません。元の関心が消えれば（メモの削除や AI 対象外を含む）関連の言葉も消えます。広げるのに失敗しても関心はそのまま使います。
2. 送る言葉を決める。自分で足した言葉と、見つかった関心のうちユーザーが外していないもの（最大12語、`newsWords`）と関連の言葉（最大4語）。これだけを外部へ送り、メモの本文は送りません。外した言葉は次回以降も送りません。
3. Googleニュース RSS（日本語・英語版）と Hacker News 検索から公開日時つきの記事を集め（日本語の関心は、関心探しで一緒に返させた英語名 `english` があれば、その名前をひとつながりの語句として英語版と Hacker News でも探し、見出しに名前がそのまま含まれるものだけ残します）、Codex の Web 検索で Reddit のスレッド・公式発表・ブログを補います。Web検索はこの処理のスレッドだけで有効にし（`thread/start` の `config: {web_search: "live"}`）、App Server 全体は `web_search="disabled"` で起動します。
   検索のスレッドだけは、ツールを使わない分析用の指示ではなく検索用の指示（`SEARCH_INSTRUCTIONS`）で始めます。分析用の指示のままだと、検索せずに空の結果を返していました。Claude Code では `--tools WebSearch` で同じことをします。
4. 検索で見つかったリンクは実在を確かめたものだけ残します（Reddit は oEmbed、他はページを開き、ボット確認ページは不可）。題名と日付はページの値を使います。同じ文字体系の見出しは、言葉の中心の名前（最も長い語）を含むものだけ残します。写真ギャラリーの番号（「＜画像2 / 12＞」）は題名から外し、写真の説明だけの見出し（「（撮影：…）」）は捨て、括弧や空白だけが違う同じ見出しは1件にまとめます。
5. 残った記事が本当にその関心の記事かを、関心の理由と一緒に軽いモデルで判定し（`news-filter`）、名前が出てくるだけのもの・同名の別物を外します。判定に失敗したときは外しません。
6. 表示言語と違う見出しを Codex で訳します。記事は14日で消えます。X は有料APIのみのため対象外です。

## これまでのメモの読み込み

記憶の層は、保存したメモをその場で読むほか、導入前からあるメモを裏でまとめて読みます（20件ずつ、新しいメモから）。読み込むメモが300件以下ならそのまま始め、それより多いときは、件数と目安の時間（これまでの読み込みの中央値、なければ接続先ごとの目安）を見せて「全部読む」「最近1年だけ」「あとで」を選んでもらいます（`memoryBackfillPlan`、`BackfillPrompt.jsx`）。利用枠をしばらく使うためです。選んだ内容は保存し、「あとで」や「最近1年だけ」のときは設定の処理状況に残りの件数と「読み込む…」を出します。新しく書いたメモは、選択に関係なく、読み込みより先に処理します。

## 裏で動いている処理の表示

サイドバー左下（軌道表示では左下のアイコンと件数）に、今動いている処理（分類・既存メモの読み込み・まとめの更新・プロフィール・リンク先・ニュース・検索の準備など）を1件1行で、件数の分かるものは進み具合、それ以外は経過時間つきで出します。待っているもの（読むメモの件数、まとめの件数と更新予定の時刻）と失敗の件数も出し、押すと設定の処理状況へ移ります（`SideActivity.jsx`）。段階の詳細は行に重ねると表示されます。

## 処理の速さ

AI の1回の呼び出しには、接続先（Codex / Claude Code）を経由するだけで数秒〜十数秒かかり、残りは AI が書く量に比例します。そのため回数を減らし、同時に動かします。メモはリンクのあるものも含めて数件（既存メモの読み込みは20件）ずつ1回で読み、分類と読み込みは3件、まとめは2件、プロフィールは3件まで同時に処理します（Codex は同時に投げても1回分の時間で返ることを確認済み）。まとめの自動更新は、カテゴリの最初のまとめはすぐ、以降はそのカテゴリのメモが10分落ち着き、かつ前回から6時間たってから行います（Badと評価されたものはすぐ）。

## AIの使用量

サイドバー左下（メモの軌道表示では左下のアイコン）に、接続しているAIアカウントの使用率（5時間・週）を出し、押すとリセットまでの時間と、pure. が使った分（今日・7日間、処理ごとの回数とトークン）を表示します（`ai-usage.cjs`、`AiUsageMeter.jsx`）。Codex は App Server の `account/rateLimits/read` で、利用枠を使わずに読めます（1分ごとまで）。Claude Code は処理の応答（`--output-format stream-json` の `rate_limit_event`）でしか返さないため、最後に返った値を時刻つきで保存して表示します。pure. の分は `ai_calls` の記録から集計します。

## 検索用データの準備

質問の検索に使う埋め込み（このMacの中で作り、外へは送らない）は、メモの保存・取り込み・復元のあと、少し待ってから裏で作っておきます（`EmbeddingWarmer`）。作っていないと、大量に取り込んだ直後の最初の質問が待たされるためです（5000件で約1分、作ってあれば約0.3秒）。

## 待ち時間の表示

まとめ・質問・カテゴリ候補・関連の分析と、裏で動く分類・まとめの更新・リンク先の読み込みは、`progress.cjs` が実際の段階（検索 → 原文を集める → Codexに接続 → 送信 → 考えている → 書いている → 根拠を照合 → 保存）と、分かっている数だけを画面へ送ります。件数、送った文字数、モデルと推論の強さ、書いた文字数、段階ごとの経過時間です。推論の段階は App Server の `turn/started`（応答待ち）と推論アイテムの開始（推論中）で分け、`turn/start` に `summary: "concise"` を付けて、Codexが考えの要約を返したときだけそれを表示します（受け付けないCodexでは付けずにやり直します）。見積もりの進捗率は出しません。

## 現在の限界

Codex・Claude Code 接続の利用条件、実データでの回答品質、対象Macでの操作・アクセシビリティ、署名・公証・配布は追加検証が必要です。AI 処理はユーザーの Codex / Claude の利用枠を使い、使用量の上限や見積もりはまだありません。クラウド同期、第三者プラグインの実行基盤は未実装です。
